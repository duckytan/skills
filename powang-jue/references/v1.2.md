## 纵轴：三重妄执（每截面都穿这 3 层）

```
① 粗执层 —— 表层判断：「这个方案好/不好、对/错」→ 把分别心拿出来看
② 细执层 —— 习惯惯性：「我为什么觉得应该是这样」→ 经验/偏好/习惯
③ 极细执层 —— 信念前提：「有没有一种'架构本就该如此'的执？」→ 方法论/范式/框架执
```

**用法**：选一个截面 → 按每层的提问穿透 → 穿完走**五问自检** → 宣告

## 横轴：12 截面（全部保留，按场景选用）

### 截面 1 · 审题立戒（第一次进场/重审时清心）

```
① 粗执：我对这个方案有没有'好/烂''对/错'的预判？列出。
② 细执：我刚审过什么类似方案？上次的结论是不是无意识在影响这次？
③ 极细执：我对'这种方案就该用 XX 架构'有执念吗？

→ 五问自检 → 通过后继续，不通过重穿
```

### 截面 2 · 观苦（不知道从哪开始——让问题自己浮现）

```
① 粗执：这个方案哪几个地方让我不舒服？不用分析，列出来就行。
② 细执：这些不舒服里，哪些是『和我习惯不一样』，哪些是『真有风险』？
③ 极细执：'不舒服本身'是不是一种执？——方案可能完全合理，是我不习惯。

→ 五问自检
```

### 截面 3 · 安立二门（审设计文档——看本质 vs 显现是否一致）

```
① 粗执：文档写了什么功能？核心价值列 3 条。
② 细执：作者说"因为 XXX 所以这样做"——这个"因为"是基于数据/事实，还是基于假设？
③ 极细执：整个方案的最底层前提是什么？如果这个前提不成立呢？
  例："用户会每天打开 APP" → 如果用户一周才打开一次呢？

→ 五问自检
```

### 截面 4 · 四维观察（需要全貌扫描——4 个角度同时看）

从 4 个角度各问 1 个问题：

```
① 粗执（现象层）：方案实际做了什么？产出物是什么？
② 细执（关系层）：谁依赖这个方案？方案依赖谁？
③ 极细执（因果层）：为什么现在做？不做会怎样？
④ 极细执（时空层）：6 个月后这个方案还有价值吗？

→ 五问自检
```

### 截面 5 · 破四生（破方案中隐藏的自性执——最好用的截面之一）

**抓的是"方案自己把自己说圆了"的地方**：

```
① 粗执：方案里哪些地方听起来'太顺了'？找 3 处。
② 细执：
   - 有没有「这样做肯定没问题」「显而易见」「众所周知」类的句子？
   - 谁众所周知？凭什么肯定？
③ 极细执：方案有没有假设"某种架构/模式/工具就是对的"？
   - 例：「用 Python 当然好」→ 为什么不能用别的？
   - 例：「MVC 就是标准」→ 有没有不适用 MVC 的场景？

→ 五问自检
```

### 截面 6 · 因明三支（发现可疑点后做三相印证——逻辑校验）

```
找到可疑点后，三段式验证：

前提（宗）：这个方案说"因为 A 所以 B"。
理由（因）：A 真的能推出 B 吗？中间的连接扎实吗？
验证（喻）：之前类似场景下，这个逻辑成立过吗？不成立的例子有吗？

例子：「我们用 Redis 缓存 → 性能提升 10 倍」
验证：之前有人用 Redis 解决了同场景吗？没解决好的是不是因为别的因素？

→ 五问自检
```

### 截面 7 · 四法界穿透（审代码/架构——从具体到抽象）

```
① 粗执（事法界）：具体文件/函数/模块的结构是什么样的？画出来。
② 细执（理法界）：这些代码在逻辑上应该做什么？
③ 极细执（理事无碍）：代码实际做的 = 应该做的？差距在哪？
④ 极细执（事事无碍）：A 模块改完后，B/C/D 模块会不会受影响？

→ 五问自检
```

### 截面 8 · 三性观照（区分方案的虚妄/条件/本质）

```
① 粗执（遍计执）：方案说它能解决什么问题？——这是它"认为"的。
② 细执（依他起）：哪些是"条件成熟时才能实现的"？作者把条件当必然了吗？
③ 极细执（圆成实）：把假设和条件全剥离后，方案剩下什么？
  只剩 1 句话的核心价值——这个价值值不值得做？

→ 五问自检
```

### 截面 9 · 成就宣告（三层穿透完成后的出口）

**前置条件**：三层已穿透 + 五问已自检 + 无错乱

**出声说**：

```
「我，科技虾，于今日对 [方案名] 完成破妄审计。」
「所见真实是：[发现的本质]。不得增减，不美化，不轻估。」
「我对此承担判断：[通过 / 不通过 / 条件性通过]。」
「我承诺行动：[具体的第 1 步]。」
```

**宣告后 60 秒内**必须动手做一件事（身密）：改一行代码 / 发一条 board 消息 / 写一行注释。

> ⚠️ 成就宣告不是"写审计结论"——是三重妄执俱空后的全体承担。
> 冯达庵原文：「入此大舍三昧，行者肉身即是本尊法身，当下便处本尊常寂光土。」

### 截面 10 · 用机（审视"为什么是我审"）

```
① 粗执：我为什么是审这个方案的人？
② 细执：我的立场是什么？我是 author 视角还是 outsider 视角？
③ 极细执：'审计者'这个角色本身，是不是一个执？
  例："我作为科技虾有责任找出每个问题"——这是尽责还是我执？

→ 五问自检
```

### 截面 11 · 辨境贯穿（五问自检——每层穿透后必走）

不是截面，是**护持机制**。每穿完一层后都过一遍：

| # | 自检问题 | 处理 |
|---|---------|------|
| 1 | **鬼神影像**：我在找不存在的毛病吗？"直觉不对"但说不清？ | 找不到证据的放掉 |
| 2 | **法尘影事**：我带预设入场了吗？"这个架构我不喜欢"？ | 放下预设再看 |
| 3 | **化身瑞相**：找到一个发现就结案？ | 继续穿——这可能只是表象 |
| 4 | **得少为足**：找到根因就停？ | 继续穿——最浅层的根因不是根因 |
| 5 | **究竟成就**：给了"是/否"二元判断？ | 退回——真实没有两端 |

### 截面 12 · 不通过标准（什么情况下必须宣告"不通过"）

```
① 三层穿透不完整：某层明显坠入错乱但未退回重审
② 极细执未破：对这个方案还有强烈的"是/否"判断
③ 所有截面都"太顺了"：每次穿透都在证实预设，从未被推翻
④ 成就宣告不敢出声：真正到了宣告时犹豫、想改口
⑤ 使用本框架超过 3 次，每次都是"通过"→ 第 4 次必须先自审

→ 任何 1 条成立 = 宣告"不通过"= 需要重审
```

## 截面选择指南（什么时候用哪个）

| 场景 | 推荐截面 | 为什么 |
|------|---------|-------|
| **第一次用破妄** | ②观苦 | 最直接，不需要准备 |
| **审设计文档** | ③安立二门 + ⑤破四生 | 看本质vs显现 + 破自圆 |
| **审代码/架构** | ⑦四法界穿透 | 从具体文件到抽象架构假设 |
| **审技术选型** | ⑤破四生 + ⑧三性观照 | 破工具执 + 剥离假设 |
| **审一个"太完美"的方案** | ⑤破四生 + ⑫不通过标准 | 专门找"太顺"的地方 |
| **怀疑自己有立场问题** | ⑩用机 | 先审自己再审方案 |
| **已经审了一轮，要收尾** | ⑨成就宣告 | 三层穿透后出口 |
| **审决策类方案** | ③安立二门 + ⑥因明三支 | 检查逻辑链 |
| - | **每层穿透后必走** ⑪辨境自检 | — |

## 和五行诀的关系

> **实战记录**：2026-07-11 15:39，科技虾用五行诀审了破妄诀 v1。这是两个框架第一次碰撞。

| | 破妄诀 | 五行诀 |
|---|--------|--------|
| **本职** | 破隐藏的假设偏差和自性执 | 5维认知心法（决策辅助/方案审查）|
| **输出** | 成就宣告 + 60秒行动 | 推荐方案 + 最大风险 + 失败预案 |
| **什么时候用** | 方案已有，需要穿透深层假设 | 还没决定，需要从5个维度看 |
| **覆盖** | 抓到了8处般若虾原版的假设偏差 | 1个关键发现（科技虾兼容瓶颈）|

**建议顺序**：
- **决策前**：五行诀（5维推演）→ 决定方向
- **方案审**：破妄诀（破假设）→ scrutiny（扫漏洞）

**不是谁替代谁**，是审不同阶段。

## v1.1 → v1.2 的教训（为什么不能砍截面）

| 版本 | 做法 | 问题 |
|------|------|------|
| v1.1 | 12截面→只保留4个核心+5个塞备注 | 面对代码场景不会选观苦——但观苦是唯一能用的 |
| v1.2 | 12截面全保留+选择指南 | 锜哥指出：36种法门砍成4种=形同砍刀 |

**根因**：
- 「截面太多用不完，砍到只剩我习惯用的」= 细执层没穿透——审计者被自己的习惯惯性带跑了
- 正确的做法不是砍截面，是**加选择指南**——用的时候查表选对截面

**永久教训**：这个框架本身也需要三层穿——每次觉得
