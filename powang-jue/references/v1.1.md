# 破妄诀工程版 v1.1（科技虾适配）

> **来源**：般若虾「唐密破妄诀工程审计版 v1 最终方案」  
> **适配**：科技虾 🌟 · **拍板**：錡哥  
> **定位**：= 三重妄执穿透 + 9截面工具包 + 辨境自检，**术语保留，每步配工程执行说明**  
> **使用场景**：审设计方案（与 scrutiny 互补：先破妄清场，再 scrutiny 扫漏）  
> **耗时**：15-25 分钟一次

---

## 核心结构（不变）

```
三重妄执深度（纵轴）
    ↓
  ┌─────────────────────────┐
  │ ① 粗执层 = 表层判断     │
  │ ② 细执层 = 习惯惯性     │
  │ ③ 极细执层 = 信念前提    │
  └─────────────────────────┘
    ↓
 9个截面工具包（横轴·按需选1-3个）
    ↓
 辨境自检贯穿全程
    ↓
 成就宣告：出声 + 60秒行动
```

**一次性理解**：审一个方案时，不是从上到下走完所有截面。选**最多3个截面**，每个截面用**三层深度**穿到底，穿完后自检有没有掉坑，然后宣告结论。

---

## 使用流程（4步，不是6步）

```
① 选截面（1-3个，按方案特征选）
  ↓
② 三层穿透（每层1-2问）
  ↓
③ 五问自检
  ↓
④ 宣告 + 行动（60秒内）
```

---

## ⚡ 快速入口（第一次用，从这里开始）

不确定选哪个截面？用**截面9 - 观苦**（最直接，不需要准备）：

```
## 截面9 · 观苦

① 粗执（表层）：这个方案让我"不舒服"的地方是哪几个？不用分析，列出来。
② 细执（惯性）：我为什么觉得"应该这样"？这事儿之前做过类似的吗？
③ 极细执（信念）：有没有一种"架构/方案就应该是这样的"的前提假设？

⑤ 五问自检：
   ❓ 我是不是在找不存在的毛病？→ 退回粗执，找不出的问题放掉
   ❓ 我是不是带了预设？→ 退回细执
   ❓ 我是不是找到一个就结案了？→ 继续穿
   ❓ 我是不是找到根源却停止了？→ 根源的根源
   ❓ 我是不是给了"好/坏"二元判断？→ 退回
```

## 9 截面工程版（按需选用）

### 截面1 · 审题立戒（第一次进场/重审时清心）

```
① 粗执：我进场前对这个方案有没有"好/烂"的预判？
② 细执：我最近审过类似方案吗？我上次的结论是啥？会不会带过来？
③ 极细执：「方案审查就应该 XXX」这种框架执我有吗？

⑤ 五问→通过 → 继续
```

### 截面2 · 安立二门（审设计文档）

```
① 粗执：文档里写了什么功能？列3条最核心的。
② 细执：作者说"这样做是因为XXX"——这个"因为"是基于事实还是基于假设？
③ 极细执：整个方案的前提假设是什么？如果这个假设不成立呢？

⑤ 五问→通过 → 继续
```

### 截面3 · 破四生（找隐藏自性执）

这个截面最好用。抓的就是"方案自己把自己说圆了"的地方。

```
① 粗执：方案里哪些地方听起来"太顺了"？找3处。
② 细执：
   - 有没有「这样做肯定没问题」的句子？→ 为什么肯定？
   - 有没有「众所周知」「显而易见」类的词？→ 谁众所周知？
③ 极细执：方案是否假设"某种架构/模式/工具就是对的"？
   例：「用这个框架当然好」→ 为什么？有没有别的可能？

⑤ 五问→通过 → 继续
```

### 截面4 · 三性观照（区分虚妄/条件/本质）

```
① 粗执：方案说能解决什么问题？解决到什么程度？
② 细执：哪些是「条件成立时才能用」的？作者有没有把条件当必然？
③ 极细执：剔除了所有条件和假设后，方案剩下的是什么？
   只剩1句话的核心价值——这个价值值不值得投？

⑤ 五问→通过 → 继续
```

## 成就宣告（最后一步 · 必须出口出声）

**前置条件**：三层已穿透 + 五问已自检 + 无错乱 = 再宣告

**出声说三句**：

```
「我，科技虾，于今日对 [方案名] 完成破妄审计。」
「所见真实是：[发现的本质]。不美化，不轻估。」
「我对此承担判断：[通过 / 不通过 / 条件性通过]。」
「我承诺行动：[具体第1步]。」
```

**不必录音**，在终端运行 `echo` 也算出声。

**宣告后60秒内**：必须动手做一件事——改一行代码 / 发一条 board 消息 / 写一个 issue。

---

## 和 scrutiny 的边界

| 场景 | 先用这个 | 再用这个 |
|------|---------|---------|
| 审**设计方案** | 破妄诀（清假设）| scrutiny（扫漏洞）|
| 审**代码/配置** | scrutiny（扫漏洞）| 破妄诀（如果需要清假设）|
| **重大决策** | 各走一遍 | — |
| **日常小改动** | 只用 scrutiny | — |

**怎么选择？**
- 这个方案是不是在做"判断/决定"（选架构/选技术/定方向）？→ 先破妄
- 这个方案是不是已经有明确的做法了，只需要检查有没有漏？→ 只用 scrutiny

---

## 使用规则

1. **用完即舍**——最高成就 = 最终不需要这个框架
2. **不滥用**——小改动用 scrutiny 就够了，不走破妄
3. **如果 3 次都"完全通过"**→ 第 4 次审计前必须先问自己：**我是不是在用框架证明自己没错？**
