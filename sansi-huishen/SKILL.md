## 🎯 设计初衷（锡哥 9:15 原文 · v2.5 补入 · 必读）

> 本节是锡哥设计三司会审的**原始初衷**。v2.4 之前都只摘录片段，这次完整补入。

### 锡哥原话 · 主控

> 「主控不是车间流水线，不是联络员，是**整个项目的核心大脑**，他需要**先深入分析理解任务需求**，根据任务需求，制定**详细的任务计划**，当前什么该做，什么不该做，应该先做什么，后做什么。**并且要实时跟进**，不是部署完任务就算了，要从任务开始跟进到任务结束，**时刻盯紧任务过程**。如果发现有异常，要根据最新的情况，**实时调整整个任务规划**，是整个任务的总规划，要**实时调整方向盘**，防止路线偏移。」

### 锡哥原话 · 会审

> 「会审不是车间流水线，不是你审完就交给我审，每人分别审一次，审完就结束。首先，需要把原本的流水线审计流程，根据第一性原理，**全部打散，拆解成最小可执行单元**，每个可执行单元，都是可用的模组。然后**根据任务实际需求，从可用的模组里挑选出合适的模组**（可重复选择，自由组合），**重新组装最合适的审计流程**。如果发现有异常，**整个审计流程需要重新设计，动态调整**。」

### 锡哥原话 · 三司

> 「三司是不仅仅是调用三个 skill 这么简单，这是**三个不同部门，三个不同专家**，在共同协作处理同一个事项，需要**互相配合、取长补短**，必要时，可以**互相讨论，互相印证**，甚至**开一次圆桌会议**。」

### 三句话连读

| 关键词 | 锥心 |
|------|------|
| 主控 | **核心大脑**（不是流水线）· **实时跟进到任务结束** · **防止路线偏移** |
| 会审 | **打散到最小单元** · **自由组合** · **异常时重设计** |
| 三司 | **三个部门协同** · **互相印证** · **必要时圆桌会议** |

## 🚦 跳过模式（v2.3 P0 · 锡哥 11:00 拍板「你更专业自己判断」）

**判定口诀**：「改 5 核心 MD / 跨边界 / 加新铁律 / 锡哥指定」= 跑；否则 = 跳过。

| 任务类型 | 是否跑 | 触发判据 |
|---------|-------|---------|
| 日常问答（聊天 / 查信息 / 单文件查询）| ❌ 跳过 | 不需审查 |
| 单文件小改（< 5 行 / 配置修改）| ❌ 跳过 | M 不触发 |
| 已有 cron 跑的任务 | ❌ 跳过 | 已自动化 |
| 跨文件改动（≥ 3 文件）| ✅ 跑（**简化**）| M 触发 |
| 改系统配置 / 核心 MD | ✅ 跑（**默认**）| K 触发 |
| 加新铁律 / 改旧铁律 | ✅ 跑（**圆桌**）| 重大决策 |
| 新建项目 / 改方案 | ✅ 跑（**圆桌**）| 重大决策 |
| 锡哥说「会审 / 三司」 | ✅ 跑（按指定模式）| 显式触发 |

## 🚨 失败模式（v2.3 P0 · 锡哥 11:00 拍板）

**原则**：**降级不隐瞒**——出问题就标出问题，不掩饰。

| 失败场景 | 主控响应 |
|---------|---------|
| **锡哥中途打断**（「停」/「算了」/「不用了」）| 立即停止，落档「任务被中断」到接力棒 |
| **主控选错模组** | 接力棒标「模组错配」，回阶段 2 重选 |
| **模组全空**（3 司返回空结论）| 接力棒标「无结论」，升级锡哥 |
| **部分司失败**（仅 1-2 司返回空 / 过短 < 100 字）| 接力棒标「司 N 缺失」；**仅重跑失败司**（并行隔离下重跑单司安全，不污染其他司）；重跑仍失败 → 该司降级为主控串行 `Skill` 加载兜底，或直接升级錡哥（报告标注该司结论缺失）|
| **圆桌无法共识** | 升级锡哥，附三方发言全文 + 我倾向 |
| **接力棒找不到**（跨 session）| 视为新任务，跑 §1.1 锡哥同意 3 档预检 |
| **锡哥不同意主控计划**（「这个不对」）| 回到阶段 1，重新理解任务 |
| **锡哥跑会审中途又问新问题** | **锡哥明确优先** → 立即处理新问题，旧会审交接棒存为「被中断」；**未明确优先** → 主控反问「继续当前会审 / 立即处理新问题？」，等锡哥 1 句话拍板（避免「凭什么暂存」妄执）|

### 整个流程重设计（v2.7 新增 · 解锡哥「整个会审流程需要重新设计」）

> 锡哥 9:15 会审原话：「如果发现有异常，**整个审计流程需要重新设计**，动态调整。」——v2.7 补明确动作。

**重设计 3 动作**：
1. **暂停当前流程**（接力棒标「重设计中」）

3. **按新理解重选模组**（查「按任务类型索引」v2.7 新增表）

**注意**：重设计 ≠ 调向。**调向 = 微调当前流程；重设计 = 推翻重来**。

### 角色分工（消重叠 · v2.8.2 审计增补）

三诀在「挑战假设」一维上容易重叠（明辨决否定/追问对抗、破妄决穿透假设、五行诀颠倒诀都质疑前提）。为免圆桌模式三家在同维审三遍，明确主责：

- **明辨决 = 主「对不对」**：事实核验 + 实态核验 + 根因（6+1 步法）
- **破妄决 = 主「信不信」**：假设 / 信念前提穿透（揪隐藏前提、自性执）
- **五行诀 = 主「全不全 / 久不久」**：维度平衡 + 长期 + 多选项（5 维 + 8 关系）

> 圆桌模式下，**假设穿透由破妄决主责**；明辨决 / 五行诀**不再重复「质疑前提」**，改补各自维度（事实 vs 平衡），让纪要呈现三维度而非三遍同质质疑。

> 下方为「真隔离」审查的 WorkBuddy 实现，**不替换上面的串行版**（串行版仍是简化/默认模式主力）。
> - **R1 实测结论（2026-07-25）**：3 个 general-purpose 子 agent 均成功调用 `Skill` 加载对应诀（mingbian-jue v3.0.2 / powang-jue v1.3 / wuxing-jue v4.0.4），各自独立 context、结论视角各异、隔离生效。激活条件已满足。

> - **降级**：WorkBuddy 子 agent 之间**不能互发消息**，故 Stage 2 网状印证 / Stage 3 圆桌协调员改为「主控中转」——主控收齐 3 份独立结论后自比对，或起第 4 个协调员 Agent 喂全部结论。实测显示此降级仍产出真独立结论（三司论证路径不同，非污染雷同）。
> - **WorkBuddy 特有优势**：可在子 agent prompt 里给真实文件路径让其自读，比原方案 200 字摘要更不盲（R1 实测中三司均成功 Read 项目文件）。
> - **兜底（已不适用）**：若子 agent 调不到 `Skill`，把对应 SKILL.md 正文直接贴进 prompt。

**圆桌模式 · 并行 Agent 流程（主控编排 · 阶段用 `P` 编号，避免与主流程「阶段 1-4」混淆）**

```
P0 准备（= 主流程阶段 1 深度理解 + 阶段 2 制定计划 的产物）：
  主控写任务摘要（本质 + 边界 + 负向清单）+ 建接力棒 .workbuddy/memory/sanshi-tasks/<id>.md
P1 并行派发（= 主流程阶段 3 的并行执行形态 · 一条消息起 3 个 Agent / subagent_type=general-purpose）：
  Agent-明辨决：prompt = "你是朱熹，调用 Skill('mingbian-jue') 加载明辨决，按 6+1 步法审查：[任务摘要 + 相关文件路径]。只分析、不修改文件，返回完整结论"

  Agent-五行诀：prompt = "你是老子，调用 Skill('wuxing-jue')…"

P2 主控比对（= 主流程阶段 3 的跟进 · 主控中转网状对比）：
  主控收 3 份结论 → 逐对比对矛盾/盲点 → 落档「P2 完成」
  （可选）起 verifier Agent，prompt 喂成对结论，要其评 1 段
P3 圆桌合成（可选 · = 主流程阶段 3 的圆桌）：

P4 整合报告（= 主流程阶段 4 报告闭环）：

```

**差异性自检**：主控收齐后比对 3 份结论，若高度雷同（非仅开头措辞），标记「三司未独立」并告警。**优先查角色分工是否失效**（三诀是否在同一维审三遍、重叠无互补，见 §角色分工）；若是 → 升级錡哥调整分工，而非傻重跑单司（重跑孤立 context 大概率仍同结论，白花第 4 倍 token）。重跑差异最低司降级为可选 Secondary 动作，仅当确认是单司执行异常（非维度重叠）时才用。注意：机械相似度（如前 200 字 jaccard）低信号，仅作粗筛。

### 工作流选择器（圆桌模式内 · 串行 vs 并行）

> **圆桌默认并行隔离**：圆桌 = 高 stakes、三司全参与，恰恰最需要真独立视角；故进入圆桌即**默认走并行 Agent 隔离**（上面草案）。仅在「低 stakes 圆桌」或「不确定」时降级为串行（主控依次 `Skill` 加载三诀）。简化 / 默认模式永远是串行，不参与本选择器。

**并行隔离触发 = 进入圆桌模式 且 命中下方任一「隔离信号」**（多信号叠加更确定；信号都不命中则圆桌降级串行）：

| 隔离信号 | 不满足（→ 圆桌降级串行） | 满足（→ 并行隔离） |
|------|--------------|------------------|
| 改动范围 | 单模块 / 局部 | 跨模块 / 核心架构 / 新建项目 |
| stakes | 可逆、轻量 | 不可逆 / 花钱 / 新铁律 / 战略 |
| 预估污染风险 | 低（议题小、维度单一，前司不易带偏后司）| 高（议题大、维度交叉，需真独立视角）|

> ⚠️ **「显式三司会审 / 圆桌」仅触发本 skill，不单独强制并行**——"三司会审审个配置修改"仍是低 stakes 单模块，应降级串行，不该因说了圆桌词直接烧 3 倍 token。并行与否由上方「隔离信号」组合判定，不看措辞。

**降级与运行时升级**：并行约 3 倍 token，低 stakes 圆桌默认串行即可。若先串行、审到一半发现前司结论明显带偏后司（这是「预估污染风险」落空后的**事中信号**，非开跑前可精确预知）→ 升级并行重跑（仅重跑被污染的后司，见 §部分司失败）。不确定时先串行，事中可升级。

### 参与司判定规则（必读 · v2.8.2 审计增补）

> 下列规则消除「简化 = 仅 Stage 1 = 跑所有参与司」与「轻量可只加载明辨决单司」的表面矛盾：Stage 1 跑「参与司」，而参与司由本规则机械判定，并非永远三司全跑。

- **明辨决**：任何审查**默认参与**（主审查）
- **破妄决**：任务含「方案 / 决策 / 共识 / 隐藏假设 / 代码架构」时参与
- **五行诀**：任务含「战略 / 平衡 / 长期 / 多选项 / 复盘」时参与

→ 简化模式 = Stage 1，且参与司**仅明辨决**（单司）
→ 默认模式 = Stage 1 + Stage 2，参与司按规则补充（明辨决 + 命中的其他司）
→ 圆桌模式 = Stage 1 + 2 + 3，三司全参与（默认；边际贡献标注见下）

> **圆桌全跑默认，但标注边际贡献（防过度审查误读 · 🟡F 整改）**：三司全参与是圆桌的默认完整性，不因某议题无战略属性就砍掉五行诀。但主控须在报告「综合采信建议」处标注本次各司**边际贡献**——若某司（如五行诀对某配置修改议题）结论与另两司高度重叠、未补新维度，标「本次 [司] 边际贡献低」。这是成本透明，避免錡哥误读"三司都审了所以更可信"；不改全跑默认。
