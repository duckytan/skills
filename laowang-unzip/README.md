# 老王解压 · laowang-unzip

**一句话**：从论坛、网盘下载回来的一堆"看着像视频、其实全是压缩包"的东西，全丢给它。它自己解压、自己找密码、自己拆套娃、自己挑垃圾、自己判断能不能删；**你删过一次的广告，它下次会自己记住**。你只需要最后看一眼报告。

> 当前版本 v3.7.6 · 适用 Windows

---

## 一、先说说你现在的活是怎么干的

### 1. 一个一个解压，解到手酸

下载回来一百多个文件，选中一个 → 右键 → 解压到当前文件夹 → 弹密码框 → 输密码 → 等 → 关掉 → 下一个……

一晚上就这么没了。

### 2. 后缀名全是假的，得手动改

明明是压缩包，后缀却是 `.mp4`、`.jpg`、`.txt`，甚至是 `.exe`，有的干脆没有后缀。双击打不开，你得自己猜、自己改成 `.7z` 或 `.rar`。改错了还不行，得再猜一次。

### 3. 密码记不住

这批是"上老王论坛当老王"，那批是文件名后面括号里那串乱码，还有的包密码写在压缩包里的某个 txt 里。一个个试，试到怀疑人生。

### 4. 压缩包套压缩包

解出来一看，里面又是压缩包；再解，还是压缩包。五层六层，鼠标点烂了。

### 5. 解出来的东西还得自己挑垃圾

（这条你可能没想到）

解完之后文件夹里混着一堆没用的：`.DS_Store`、`Thumbs.db`、`__MACOSX` 文件夹、以 `._` 开头的文件、0 字节的空文件、几 KB 的"最新地址.txt""加群.txt"，还有伪装成安装软件的小程序。

一个个挑、一个个删，比解压还累。

### 6. 同一个包下了两遍，白占空间

论坛帖子里重复下载、网盘里重复保存。解完才发现里面一模一样。硬盘被这些重复内容吃掉几十上百 GB。

### 7. 解压跑到一半，盘满了

（这条你可能没想到）

解压需要"源包 + 解出来的东西"同时存在，等于占双倍空间。跑到一半磁盘变红条，前面全白干。

### 8. 跑到一半断电、卡死、或者把窗口关了

（这条你可能没想到）

几十 GB 的包要解两个小时。中途电脑休眠了、软件不动了、你手滑把窗口关了。再打开——不知道解到哪了，只能从头来。

### 9. 提示"文件损坏"，其实根本没坏

（这条你可能没想到）

有的包被人为在前面塞了一段垃圾（最常见的是塞一段假视频头），压缩软件打开就直接报损坏。你以为是坏包，删了重下，重下还是"坏的"。

### 10. 网盘下载被切成一段一段的

（这条你可能没想到）

超过 4GB 的文件，网盘会切成 part1、part2、part3……中间还可能断过。拼不齐就解不开，你还以为是资源本身有问题。

### 11. 分卷的第一卷被改了名

（这条你可能没想到）

有的发布者为了防和谐，把第一个分卷的后缀改成"删除"，比如 `xxx.7z.001删`。压缩软件认不出来，也就解不开。

### 12. 解完源包不敢删

（这条你可能没想到）

删早了吧，回头发现没解成功，网盘又限速，重下要一整天；不删吧，硬盘真的不够了。删还是不删、什么时候删，全靠感觉。

### 13. 隔了几天，忘了哪个解过哪个没解

（这条你可能没想到）

下载目录堆了几百个文件，解了一半，过几天全忘了。只能重新看一遍，重复劳动。

### 14. 卡死了，但不知道是真死还是在干活

（这条你可能没想到）

解一个二十几 GB 的大包，界面上好几分钟不刷新。你不知道该等还是该关：关了吧怕白解，不关吧又怕它真的死了。

---

### 15. 解完剩一堆空文件夹，删起来很烦

（这条也是你提醒的）

一个包里那个广告文件夹，里面的广告文件你删了，文件夹还杵在那儿；套娃解了好几层，每层都留下几个空壳。单独去删这些空文件夹，点进点出，比解压本身还烦。

### 16. 同一个广告，这次删了，下次还得再删一遍

（这条是你想到的"垃圾库"，我把它单列出来）

老王论坛的广告是有套路的。今天发个 `最新地址.txt`，明天发个 `新地址2.txt`，内容几乎一模一样。你每次都得重新看一遍、重新删一遍——**它记不住你上次删过什么**。

## 二、这些事，它是怎么给你解决的

### 对应痛点 2（假后缀）→ 不看名字，直接读文件的"身份证"

它不看你文件名写的是什么，而是直接读文件开头的那几个字节——这是压缩包永远改不掉的"身份证"。所以 `.mp4` 也好、`.jpg` 也好、没后缀也好，它一眼认出来。

再进一步：
- 开头被塞了垃圾的，它自动把真包从垃圾后面**切出来**；
- 文件头被人动过手脚的（比如该是 `PK` 被改成 `UA`），它自动**改回来**。

### 对应痛点 1（一个个解）→ 全部丢进去，剩下它来

把这次下载的东西放进一个文件夹，跑一次。它自己排队、一个一个解、解完出一份报告。中间不用你管。

### 对应痛点 3（密码记不住）→ 密码它自己找，而且会越用越准

- **从文件名里抠**：名字末尾括号里的那串（`xxx（sX8uRvp4Ld73）.tar` → 密码就是括号里的），还有"解压码：""密码：""提取码：""密码="后面的内容，它都自动拿来试。
- **从文件夹名里抠**：文件夹名字末尾带括号的，同样算。
- **上一层的密码传给下一层**：套娃包外面解开了，里面那个直接用同一个密码试。
- **你的密码库**：你常用的密码存一份，以后自动先试这些。
- **越用越快**：哪个密码成功解开的次数多，下次就排前面先试。用得越久，试得越准。
- **最后的兜底**：要是外面都找不到，它还会去已经解出来的 txt 文件里翻——常见的"密码.txt"，或者内容里写着"解压密码：xxx"，找到就自动用上。
- **随时补一条**：你想起来一个新密码，告诉它一句，它会拿这个新密码把之前所有密码不对的包**重新试一遍**。

### 对应痛点 4（套娃）→ 自动往下挖，挖到底为止

解出来还是压缩包，它接着解，一直解到没有压缩包为止。也做了保护：最多挖 8 层，防止碰上坏包没完没了。

### 对应痛点 5（垃圾）→ 自动挑垃圾，还分两种待遇

- **零风险的**（`.DS_Store`、`Thumbs.db`、`__MACOSX`、0 字节空文件）→ 直接清掉，报告里告诉你删了什么。
- **有点风险的**（广告 txt、诱饵小程序、广告文件夹）→ 它不擅自动手，**列成清单等你点头**。
- 有一条铁规矩：**跟密码有关的文件绝对不删**（比如"密码.txt"），免得把你自己的线索删了。

### 对应痛点 6（重复包）→ 自动认亲，不重复干活

它会给每个文件算一个"指纹"。内容一样，指纹就一样。一旦发现两个文件指纹和大小完全一致，就只解一个，另一个标成"重复，等你定夺"。

而且——**它永远不会因为"重复"就自动删你的东西**，只标记，等你拍板。

### 对应痛点 7（盘满）→ 开工先算账

开工前先看：还剩多少空间、回收站里压着多少东西。按"这批文件大小 × 1.5 再加 6GB 缓冲"估算够不够用。不够的包直接跳过，绝不硬上，避免解一半卡死在半路。

另外，剩余空间少于 20GB 它就直接不开工。

还有个细节：它会**在开工前先清空回收站**——因为回收站里的东西其实还占着硬盘。这样能多腾出空间，也是"解完就能删源包"能成立的前提。

### 对应痛点 8（中断）→ 断了就断点续跑，不用从头来

它每处理一个文件都记一笔账。断电、崩溃、关了窗口都无所谓。重新跑一次，它会自己接着没做完的地方继续，已经解好的不会重解。

### 对应痛点 9（假损坏）→ 它会自己先"修"

前面塞垃圾的、文件头被动过的、分卷没拼起来的，它都会先尝试自己修好，再解。修了什么，报告里标得清清楚楚（切出来的包、改回来的包、拼起来的包）。

> 修出来的包会当成新任务走完整流程，照样要过后面的安全删除检查——不会因为是"修出来的"就降低标准。

### 对应痛点 10（4GB 分段）→ 自动拼回去

认得出网盘切段的特征，自动去找同目录的后续分段，拼成一个完整的包再解。

### 对应痛点 11（首卷改名）→ 认得出"删除"后缀

带"删除""删"后缀的首卷它认得出来，该拼的拼、该解的解。

### 对应痛点 12（不敢删源包）→ 有硬规矩：12 道检查全过才删

不是"解完就删"，而是"**解完、验完、确认东西都在、没有失败项、没有风险标记**"，12 道检查全部通过，才删源包。

而且删是**扔进 Windows 回收站**，不是彻底删——删错了能还原。

最保守的一条：**密码类的失败，绝对不删源包**。宁可留着让你再想想。

> 有一个点要提醒你：默认情况下，**这一批跑完之后回收站会被清空**（不清空就腾不出空间）。如果你想留着回收站里的副本当保险，提前说一句"别清回收站"就行。

### 对应痛点 13（忘了解过哪个）→ 有台账、有报告

每个文件的状态都记在账上：下过、判过、解过、失败了是因为什么、删没删。

处理完会给一份报告，讲清楚这几件事：
- 这批一共干了什么；
- 哪些成功了；
- 哪些没成功、为什么（缺密码？包坏了？）；
- 有哪些要你定夺（重复包留哪个、垃圾要不要删）；
- 省了多少空间。

**没解成功的包会一直留着**，下次还能重试，不会悄悄消失。

### 对应痛点 14（不知道是不是卡死）→ 有看门狗

它划了两道线：

1. 单个包最多解 **90 分钟**，超了就掐断；
2. 同时看**真正的产出**（解出来的文件数量、字节数）——如果 **30 分钟**一点进度都没有，就判定卡死，自动掐掉、记一笔、继续下一个。

> 为什么不是看 CPU 忙不忙？因为磁盘读写打满的时候，CPU 也会停下来，光看 CPU 会把"正在努力干活"误判成"死了"。所以这里看的是实际产出。

掐掉之后，最多再重试 1 次。

### 对应痛点 15（空文件夹）→ 顺手清掉空壳

一次跑完，它会回头看：**哪些文件夹是因为这次删东西才变空的**，然后把它们从里到外一层层收掉。里面但凡还剩一个文件，它就不动。

你原来就有的空文件夹（不是这次弄出来的）它不碰——只清自己弄出来的空壳。

想手动清也行，有一条专门的命令，而且**默认只是"给你看看"**，要加一句"真删"才动手：

```
python pipeline.py prune-empty            ← 只看，列出哪些是空的
python pipeline.py prune-empty --apply    ← 真删
```

### 对应痛点 16（同一个广告删不完）→ 它会记住，而且**只记你点过头的**

它有一个"垃圾库"。你确认删掉的广告/垃圾文件，会被记下来（连同这个文件长什么样——按**内容**记，改名字也认得出来）。**下次再解出来同样的东西，解压完就顺手删了，不用你再管一遍。**

这里有一条我用命担保的规矩，请你一定要知道：

> **机器永远不会自己往库里记东西。**
>
> 只有**你亲口确认删过**的、或者你**自己跑命令加进去**的，才会进库。它自己觉得是垃圾的，永远只能"提个醒"，不能自己说了算。

为什么这么死板？因为**猜错密码没事**（大不了多试一次），**猜错垃圾要出事**（真删你的文件，而且删完你还看不出来）。要是让它自己学，它第一次猜错、记下来，以后每次见到同类的都照删——这种错你根本发现不了。

另外三条保护：

- 名字里带**"密码""解压码""提取码"**的文件和文件夹，**永远不查库、不入库、不删**。
- **整批点头**（一次批准一堆）→ 只按**内容**记，不牵扯名字；**单独点某个文件**的头 → 连名字一起记。
- 想看看它记了什么、或者反悔删掉某条，都有命令：

```
python pipeline.py junk-stats               ← 看它记住了什么
python pipeline.py junk-stats --forget name:最新地址.txt   ← 反悔，忘掉某一条
python pipeline.py junk-learn "某个文件路径"  ← 你手动教它一次
```

## 三、安全上的三条底线

| 情况 | 它会怎么做 |
|---|---|
| 明显没用、零风险的垃圾 | 直接清掉，报告里写明白 |
| 有点风险、拿不准的 | **列清单等你确认**，你同意才动 |
| 你确认过、已经记进垃圾库的 | 按"零风险"处理，下次解完顺手删（这正是你点头过的） |
| 高风险（涉及密码失败的源包、重复包） | **永远不动**，只报告 |
| 空文件夹 | 只清这次删东西才变空的，从里到外一层层收；里面还有东西就不动 |

另外：

- 它自己的程序、账本、**密码库、垃圾库**都在保护名单里，**绝对不会被自己误删**。
- 你的个人密码库和垃圾库**不会上传、不会外泄**，只存在你自己电脑上（也不进版本库）。
- 记住一件事：**垃圾库里的每一条都是你点过头的**，机器不会自己往里加。觉得记错了，一条命令就能删掉（`junk-stats --forget`）。
- 想先看一眼再动手？跑一次"只看不干"模式，它只列清单，**不解压、不删任何东西**；清空文件夹那条命令默认也是只看。

## 四、怎么用（大白话版）

### 先准备两样

1. 电脑上装好 **7-Zip**（免费的那个压缩软件，装了就行）。
2. 用 **Windows 电脑**。因为它靠 Windows 回收站保证"删了能找回"；在 Mac / Linux 上删了就真没了。

### 然后四步走

**第 1 步 · 归集**

新建一个文件夹，把这次下载的全部东西（包括里面的子文件夹）原样挪进去。

**不用改名、不用分类、不用管哪个是压缩包**——只管挪。

**第 2 步 · 先试跑（强烈建议）**

跑一次"只看不干"。它会告诉你：扫到多少个文件、哪些是压缩包、哪些是垃圾、大概需要多少空间。

这一步**不会解压、不会删东西**，纯看。

**第 3 步 · 正式跑**

确认没问题就正式开跑。它会自己排队、解压、试密码、拆套娃、清垃圾、失败重试，一条龙。

期间你可以去干别的。中途断了（关机、崩溃、手滑关窗口）都不要紧，**重新跑一次它就接着来**。

**第 4 步 · 看报告**

跑完会有一份报告。重点看三块：

- 哪些**没成功**、为什么；
- 哪些**等你定夺**（重复包留哪个、垃圾要不要删）；
- 这次**省了多少空间**、删了什么。

照着报告提示把剩下的事处理掉就完事了。

### 日常（可选）

- **想起一个新密码** → 告诉它一句，顺手把之前失败的包全部重试一遍。
- **想知道密码库里都有啥、哪个最准** → 一看就列出来了（按成功次数排序）。
- **看到一个新的广告文件，想让它以后自己删** → 丢一句命令教它一次（`junk-learn`），以后就不用管了。
- **想看看它记住了哪些垃圾、或者反悔** → `junk-stats` 一条命令，能看能删。
- **想一次性把下载目录里的空文件夹全清掉** → `prune-empty`（默认只看，加 `--apply` 才真删）。
  顺带一提：你确认删过垃圾之后，**被删空的那些文件夹它会当场收掉**，不用你另外操心。
- **想重跑失败的那些** → 单独一条命令。

### 给习惯敲命令的同事

所有操作都在这一个入口上（`pipeline.py`）：

```
先体检（能不能开工）      doctor
只看不干                  run --dry-run
正式跑                    run
加密码 + 立刻重试         add-password "密码" --test
看密码库（按成功次数排）  pw-stats
看垃圾库（记住过什么）    junk-stats
反悔某条垃圾记忆          junk-stats --forget name:最新地址.txt
手动教它一条垃圾          junk-learn "文件路径"
清空文件夹（默认只看）    prune-empty      （加 --apply 才真删）
重跑失败的                retry-failed
清回收站（真腾空间）      purge-recycle
重新生成报告              report
```

不同人电脑上的文件夹位置不一样，要把"处理根目录"和 7-Zip 的位置告诉它，或者写进配置文件里，一次搞定。

## 五、它做不到 / 要注意的

| 情况 | 说明 |
|---|---|
| Mac / Linux | 能扫描、能解压、能出报告；但**删除不可恢复**，也没有回收站兜底。建议只跑"只看不干"模式。 |
| 分卷少了首卷，或者首卷不全 | 拼不出来，只能重新下载。 |
| 文件头被彻底搞坏 | 修不了，会列出来让你人工处理。 |
| 网盘 4GB 分段拼接 | 逻辑上有，真实样本还在验证中。 |
| 套娃超过 8 层 | 停止下挖（防止无限循环）。 |
| 藏得特别深的嵌套包 | 可能会漏掉，这种情况会在报告里提示。 |
| 空文件夹 | 只清**这次删东西才变空**的；你自己原来建的空目录它不动（想全清跑 `prune-empty --apply`）。 |
| 垃圾库 | 是**跟着这台电脑走的**，换电脑要重新教；而且它只认你确认过的，所以刚上手那几天效果一般，越用越省事。 |

## 六、它是怎么变准的

这个工具里几乎每一条判断规则，都是从真实的 46GB、200 多个文件、上百个批次的踩坑里攒出来的，不是拍脑袋定的。

每次处理完一批，遇到的新问题会被记成"教训"。同一个问题出现两次以上，或者一次就够严重，就升级成正式规则，写进工具里。

**你用得越多，它踩过的坑越全。**

想看细节的，`references/` 目录里收了 49 条实测踩坑记录。
