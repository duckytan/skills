## 🎯 v2.8 项目状态机映射（7-20 锡哥拍板·C/D 重点 + A/B 顺带）

### ⚠️ 核心关系（防误判为过度设计）

**C（公共语料池）= D（主动大脑）的关键依赖，不是独立功能。**

- D 要「主控主动感知」必须能读到一个公共位置（不能每个 agent 各探查）
- 没有 C1 → D 的自动感知只能单机使用 → 多 agent 接力必打架
- **判定口径**：如果对多 agent 写作有帮助 → 不是过度设计
- 单 agent 场景下 C1 自动退化为「主控自写自读」，不增加复杂度

### 4 大设计动机

- **C【重点】多 agent 公共语言** — 不同 agent 看同一项目 = 同状态标签
- **D【重点】主动大脑** — skill 从被动工具升级为主动感知 + 自动选模式
- **A【顺带】减少锡哥教学负担** — 锡哥说「审查 X」= AI 立刻开干
- **B【顺带】cron 自动触发** — 方案文件改动 → 自动调度三司会审

### 1. 统一状态标签（C 重点）

```
[格式] sanshi-state:<项目 ID>-<10 状态枚举>-<置信度 0-100>%
[例]   sanshi-state:png-card-redesign-3-方案已出-85%
```

| 要素 | 说明 |
|------|------|
| **项目 ID** | 用方案文档目录名（如 P31-png-card-redesign/）|
| **状态枚举** | 10 选 1（详下表）|
| **置信度** | 反映信号清晰度 |

### 2. 10 状态枚举表（v2.8 起步版）

| # | 状态 | 含义 | 典型信号 |
|---|------|------|---------|
| 1 | **计划中** | 仅有 future-plans/ 提到 | `ls future-plans/` 单文件 |
| 2 | **方案讨论中** | 多方案对比 + AI 出 2+ 候选 | 2+ 方案同主题 |
| 3 | **方案已出** | 单一方案已写，未拍板 | 1 个 v?-design-proposal.md |
| 4 | **方案已定** | 锡哥拍板 + A/B/C/D 选项记录 | 锡哥关键词「拍板 A/B」|
| 5 | **实施计划已出** | 拍板后写 SOP/实施指南 | P??-实施指南.md |
| 6 | **实施中：N/M** | 实操进度可量化 | 文案「3/5 完成」|
| 7 | **实施完成** | 全部 deliver 完成 | 交付物齐 + 文档落档 |
| 8 | **已落地·维护中** | 自动化已跑 + 健康检查通过 | ≥ 24h 自动化正常 |
| 9 | **升级改造** | v2/v3 关键词 + 改动已在跑 | grep "v[0-9]" |
| 10 | **归档/废弃** | 无自动化 + 无改动 ≥ 30 天 | 文件 mtime 过期 |

### 3. 公共语料池 C1（C 重点）

> **WorkBuddy 适配**：WorkBuddy 为单机单主 agent，原「多 agent 公共语料池」退化为「**主控自写自读**」——C1 不再是防多 agent 打架的公共位置，而是**跨 session 恢复状态**的本地状态文件。功能不变，复杂度自动降低。

```
路径  ：.workbuddy/memory/sanshi-states/<项目 ID>.json（工作区相对，随项目走）
格式  ：{state, lastUpdate, agentSource:"workbuddy", history[10]}
写方  ：主控（WorkBuddy 主 agent）
读方  ：主控 · 下次 session 恢复用
铁律  ：写之前必须 read · 不能直接覆盖（保留 history 便于回溯）
```

### 4. 主控自动感知 D1（D 重点）

```
接锡哥指令「审查 X 项目」
    ↓
读 .workbuddy/memory/sanshi-states/<X>.json（如有）
    ↓
无 → 自动探查（git log / WorkBuddy 自动化 / 文件 mtime）→ 推断状态
    ↓
有 → 用已有，但可被新信号覆盖
    ↓
自动选模式：
  状态 1-3 / 9-10 = 简化模式
  状态 4-5       = 默认模式
  状态 6-8       = 圆桌模式
    ↓
自动选模组子集：
  状态 2  方案讨论中 = MB-04 追问 + WX-05 知几
  状态 6  实施中   = MB-06 实态 + MB-07 推荐
  状态 8  维护中   = MB-01 Pre-Mortem + PW-01 共识
```

### 5. 主动调度 D2（D 重点）

| 触发 | 主控自动行为 |
|------|-----------|
| 锡哥说「审查 X」| 自动识别 + 自动模式 + 自动模组 |
| 锡哥拍板「采纳方案 A」| 自动写 sanshi-states + 推进 3 → 4 |
| 自动化任务连续跑通 ≥ 24h | 自动探查 → 跳到 8 = 维护中 |
| 改动 ≥ 30 天且无自动化 | 自动跳到 10 = 归档报告 |

### 6. 异常感知 D3（D 重点）

| 异常信号 | 自动动作 |
|---------|---------|
| sanshi-states 7 天未更新但 git log 显示改动 | 升锡哥「状态机漂移」|
| 多 agent 同时段写 | log 异步写 + 警示锡哥 |
| 推断 vs 锡哥拍板冲突 | **以锡哥拍板为准**（铁律 L）|

### 8. 自动触发 B1（B 顺带 · WorkBuddy 自动化）

> **WorkBuddy 适配**：原 OpenClaw 的 cron 触发 → 映射到 WorkBuddy「自动化(automations)」。可选功能，需用户显式创建一条自动化任务。

| 项 | 说明 |
|----|------|
| 触发 | 方案 / future-plans 目录改动 → 建议将状态推进到 4 |
| 动作 | 由自动化定时调度三司会审（默认模式）|
| 冷却 | 同一项目状态变更 24h 内不重复触发 |
