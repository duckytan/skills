## 阶段 2 · 破妄诀（穿透隐藏假设 / 妄执）

> 立场：这个 skill 我「以为」成立的隐含前提，哪些其实不成立？

1. **妄执：「删除是安全可逆的」**
   破：仅在 Windows 成立。非 Windows 走 `os.remove` 永久删（SKILL.md:18）。若用户误以为「反正进回收站能找回」而在 Linux/macOS 上跑——删除不可还原。这是最该在主 README 用大白话强调的点（当前只在 §0 技术声明里，普通用户未必读到）。

2. **妄执：「单线程是因为逻辑简单」**
   破：注释（scheduler.py:4-9）给出硬理由——7z 已占满机械盘带宽，并行 < 1.2x 且失败率更高；且串行才有确定性去重。这是**经过权衡的设计**，不是偷懒。审查时差点误判为「该并行优化」，破妄后确认不该动。

3. **妄执：「文档里的代码路径就是真的」**
   破：failure-matrix.md 写的 `pipeline/sched/...`、`pipeline/core/...` 是**旧目录树残留**（F1）。「文档说实现在某处」≠「实现真在那儿」。本次靠实读代码才戳破，不能信文档的「实现：」指针。

4. **妄执：「枚举数 25/26 随便哪个都行」**
   破：差的那 1 个（`UNSAFE_PATH`）恰恰是**安全相关的最高危枚举**（zip-slip 逃逸）。少记它不只是数字错，而是把「最该被记住的安全分支」从文档里漏掉了（F2）。

5. **妄执：「rc==0 就算解压成功」**
   破：代码显式要求 `rc==0 AND "Everything is Ok" AND 输出非空 AND 无 0 字节残根 AND 无 zip-slip 逃逸`（scheduler.py:597-647）。「rc==0」单独不够——这是 v1 真事故换来的（OUTPUT_EMPTY / OUTPUT_ZERO_ROOTS 两个专门枚举）。
