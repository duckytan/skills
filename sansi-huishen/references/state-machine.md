## 🎯 v2.8 项目状态机映射（7-20 锡哥拍板·C/D 重点 + A/B 顺带）

### ⚠️ 核心关系（防误判为过度设计）

**C（公共语料池）= D（主动大脑）的关键依赖，不是独立功能。**

- D 要「主控主动感知」必须能读到一个公共位置（不能每个 agent 各探查）
- 没有 C1 → D 的自动感知只能单机使用 → 多 agent 接力必打架
- **判定口径**：如果对多 agent 写作有帮助 → 不是过度设计
- 单 agent 场景下 C1 自动退化为「主控自写自读」，不增加复杂度

### 4 大设计动机

- **C【重点】多 agent 公共语言** — 不同 agent 看同一项目 = 同状态标签
- **D【重点】主动大脑** — skill 从被动工具升级为主动感知 + 自动选模式
- **A【顺带】减少锡哥教学负担** — 锡哥说「审查 X」= AI 立刻开干
- **B【顺带】cron 自动触发** — 方案文件改动 → 自动调度三司会审

### 1. 统一状态标签（C 重点）

```
[格式] sanshi-state:<项目 ID>-<10 状态枚举>-<置信度 0-100>%
[例]   sanshi-state:png-card-redesign-3-方案已出-85%
```

| 要素 | 说明 |
|------|------|
| **项目 ID** | 用方案文档目录名（如 P31-png-card-redesign/）|
| **状态枚举** | 10 选 1（详下表）|
| **置信度** | 反映信号清晰度 |

### 2. 10 状态枚举表（v2.8 起步版）

| # | 状态 | 含义 | 典型信号 |
|---|------|------|---------|
| 1 | **计划中** | 仅有 future-plans/ 提到 | `ls future-plans/` 单文件 |
| 2 | **方案讨论中** | 多方案对比 + AI 出 2+ 候选 | 2+ 方案同主题 |
| 3 | **方案已出** | 单一方案已写，未拍板 | 1 个 v?-design-proposal.md |
| 4 | **方案已定** | 锡哥拍板 + A/B/C/D 选项记录 | 锡哥关键词「拍板 A/B」|
| 5 | **实施计划已出** | 拍板后写 SOP/实施指南 | P??-实施指南.md |
| 6 | **实施中：N/M** | 实操进度可量化 | 文案「3/5 完成」|
| 7 | **实施完成** | 全部 deliver 完成 | QQ 推送 ✅ + 文档落档 |
| 8 | **已落地·维护中** | cron 已跑 + 健康检查通过 | ≥ 24h cron 正常 |
| 9 | **升级改造** | v2/v3 关键词 + 改动已在跑 | grep "v[0-9]" |
| 10 | **归档/废弃** | 无 cron + 无改动 ≥ 30 天 | 文件 mtime 过期 |

### 3. 公共语料池 C1（C 重点）

> **与 D1 关系**：C1 是 D1 「主控自动感知」的关键依赖——D 能跨 agent 感知，C1 必须存在。
> **场景退化**：单 agent 下 C1 = 主控自写自读 · 多 agent 下 C1 = 公共位置防状态打架

```
路径  ：~/.agents/sanshi-states/<项目 ID>.json
格式  ：{state, lastUpdate, agentSource, history[10]}
写方  ：科技虾(main) / 般若虾(prajna) / 经济虾(econ) / 码农虾(code)
读方  ：任意 agent · read-only via path
铁律  ：写之前必须 read · 不能直接覆盖（保留历史）
```

### 4. 主控自动感知 D1（D 重点）

```
接锡哥指令「审查 X 项目」
    ↓
读 ~/.agents/sanshi-states/<X>.json（如有）
    ↓
无 → 自动探查（git log / cron / 文件 mtime）→ 推断状态
    ↓
有 → 用已有，但可被新信号覆盖
    ↓
自动选模式：
  状态 1-3 / 9-10 = 简化模式
  状态 4-5       = 默认模式
  状态 6-8       = 圆桌模式
    ↓
自动选模组子集：
  状态 2  方案讨论中 = 明辨决·追问性对抗 + 五行诀·知几诀
  状态 6  实施中   = 明辨决·实态核验 + 推荐行动
  状态 8  维护中   = 明辨决·Pre-Mortem + 破妄诀·共识妄执
```

### 5. 主动调度 D2（D 重点）

| 触发 | 主控自动行为 |
|------|-----------|
| 锡哥说「审查 X」| 自动识别 + 自动模式 + 自动模组 |
| 锡哥拍板「采纳方案 A」| 自动写 sanshi-states + 推进 3 → 4 |
| cron 推送成功 ≥ 24h | 自动探查 → 跳到 8 = 维护中 |
| 改动 ≥ 30 天无 cron | 自动跳到 10 = 归档报告 |

### 6. 异常感知 D3（D 重点）

| 异常信号 | 自动动作 |
|---------|---------|
| sanshi-states 7 天未更新但 git log 显示改动 | 升锡哥「状态机漂移」|
| 多 agent 同时段写 | log 异步写 + 警示锡哥 |
| 推断 vs 锡哥拍板冲突 | **以锡哥拍板为准**（铁律 L）|

### 7. 阶段 1 加项目状态字段 A1（A 顺带）

```markdown
## 任务本质卡片（v2.8 必填）

### 项目状态（10 选 1）
[ ] 1-计划中 / 2-方案讨论中 / 3-方案已出
[ ] 4-方案已定 / 5-实施计划已出 / 6-实施中：N/M
[ ] 7-实施完成 / 8-已落地·维护中
[ ] 9-升级改造 / 10-归档/废弃

[原有：表面需求 / 真实需求 / 边界 / 负向清单]
```
